# Public status page

> Task: **T-012** — public status page (BUSINESS_REPORT.md §9, App.A #9).
> Source dir: [`status/`](../status/). Workflow: [`.github/workflows/status-page.yml`](../.github/workflows/status-page.yml).

The lvcodex status page is a **static Hugo site** generated by
[cstate](https://github.com/cstate/cstate). It is rebuilt by GitHub
Actions on every push that touches `status/**` and served from GitHub
Pages at:

```
https://itumor.github.io/LV-exam/status/
```

(Placeholder URL — see *Deployment* below for how to wire Pages once
the repo enables it.)

The exam app links to this URL from a `System Status` link in the
footer of `latvian-a2-exam-app/index.html`.

---

## How it works

```
  status/config.yml                    declarative: title, brand, systems[]
  status/content/issues/*.md           one markdown file per incident
  status/themes/cstate/                fetched by CI from cstate@v6.5.0
                  │
                  ▼  hugo --config status/config.yml --source status
  status/public/                       static HTML+CSS+JS+RSS
                  │
                  ▼  peaceiris/actions-gh-pages
  gh-pages branch  ───►  GitHub Pages  ───►  https://…/status/
```

No runtime. No database. No backend. The page is a frozen snapshot of
the markdown in `status/content/issues/` at build time.

## Adding a new system

A "system" is a row on the status grid. To add one:

1. Open [`status/config.yml`](../status/config.yml).
2. Append an entry under `params.systems`:

   ```yaml
   - name: "Background Workers"
     description: "Async jobs (snapshots, email digests)."
   ```

3. Commit and push. The site rebuilds and the system shows green
   until an incident affects it.

The `name` is the matching key — incidents reference it verbatim in
their `affected:` front-matter list, so once you have history under a
given name **don't rename it casually**: you'd also have to search-and-
replace across every file in `status/content/issues/`.

Existing systems (current as of T-012):

| Name | What it covers |
|---|---|
| API | REST endpoints served by `server.py` on Fly.io |
| Database | SQLite primary store (Postgres post T-021) |
| AI Scoring (Groq) | LLM-backed scoring for writing & speaking |
| Stripe Webhooks | Billing event delivery & subscription lifecycle |
| Frontend | Static exam app served from `/latvian-a2-exam-app` |

## Logging an incident

Full operator runbook lives in [`status/README.md`](../status/README.md).
Short version:

1. Create `status/content/issues/<yyyy-mm-dd-slug>.md`:

   ```markdown
   ---
   title: "Brief headline"
   date: 2026-05-23T14:05:00Z       # UTC, ISO-8601
   resolved: false
   severity: disrupted               # down | disrupted | notice
   affected:                         # must match config.yml `systems[].name`
     - API
     - AI Scoring (Groq)
   section: incident                 # incident | maintenance | notice
   ---

   First-status body. What we know, what we are doing.
   ```

2. Append updates as `## <UTC timestamp>` headings inside the same file
   (newest at the bottom).

3. Resolve by:
   - Setting `resolved: true` in the front-matter.
   - Adding a final `## Resolved — <UTC timestamp>` heading.

4. `git commit && git push`. The page redeploys in ~2 minutes.

### Severity levels (cstate convention)

| Level | Meaning | Badge color |
|---|---|---|
| `down` | Hard outage — feature completely unavailable | red |
| `disrupted` | Degraded — slow, partial, or flaky | amber |
| `notice` | Informational (e.g. planned maintenance announcement) | blue |

## Subscribing to updates

cstate exposes an **Atom feed** at:

```
https://itumor.github.io/LV-exam/status/index.xml
```

Any RSS/Atom reader can subscribe (Feedly, NetNewsWire, Thunderbird,
Inoreader, `rsstail`, etc.).

### Email subscriptions — deferred

cstate does **not** ship an email subscription mechanism, and we have
not bolted one on in T-012. This is explicitly flagged in
[`status/README.md`](../status/README.md). Two paths for the follow-up
ticket:

1. **Hosted bridge** — point Buttondown / EmailOctopus / Mailchimp at
   the Atom feed; they fan out a digest on change. Cost: ~€0–10/mo.
2. **Self-hosted** — small worker that polls `index.xml`, diffs
   against the previous snapshot, and emits SMTP via the existing
   mail provider (post-T-014 once Postmark/SES is on-deck).

File the follow-up as **T-012b**.

## Deployment

### One-time setup (repo admin)

1. In GitHub → **Settings → Pages**: set source to **Deploy from a
   branch**, branch **`gh-pages`**, directory **`/ (root)`**.
2. Confirm the published URL — if the repo is renamed, also update:
   - `status/config.yml` → `baseURL`
   - `latvian-a2-exam-app/index.html` → footer `href`
   - This document.
3. Optional: add a custom domain (`status.lvcodex.com`) under Pages
   settings; cstate's relative URLs handle the change.

### Per-incident flow

There is no manual deploy step. The workflow at
[`.github/workflows/status-page.yml`](../.github/workflows/status-page.yml)
fires on every push to `develop` or `main` that touches `status/**` and
publishes to `gh-pages` via SHA-pinned `peaceiris/actions-gh-pages`.

To force a rebuild without a content change, open the workflow in the
Actions tab and click **Run workflow** (`workflow_dispatch`).

### Rollback

The published artifact is just a commit on `gh-pages`. To roll back:

```bash
git checkout gh-pages
git revert <bad-sha>
git push origin gh-pages
```

GitHub Pages picks up the revert within a minute.
